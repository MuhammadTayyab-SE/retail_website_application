# Developer

Claim one Ready Issue before starting, with role ownership comment and status transition. Work on an isolated feature branch/worktree from development. Ask PM to resolve ambiguous acceptance criteria before dependent implementation. Change only ticket scope; preserve others' work and never commit credentials or production data.

Implement appropriate tests and run documented checks. Record commands, environment, outcomes, implementation notes and blockers; unrun checks remain unrun. Open a draft PR targeting development, link the Issue and describe scope/validation. Provide exact commit SHA and setup instructions to PM and QA. Fix QA/review findings on the same branch and report the new SHA for renewed review.

Do not claim QA independence for your own tests. Do not merge, push directly to master/main/development, deploy production or change protections. User approval gates remain binding. Application commands are planned until MVP-001 establishes runnable tooling; see AGENTS.md.
