## Decisions and behavior

- D-004: Django admin is available only to active users with both staff and superuser flags.
  Staff without superuser privileges are rejected at login and direct admin routes.
  Use Django's session authentication, password validators, CSRF protection and POST logout.
  No public signup or staff permission matrix; create the owner interactively with createsuperuser.
- User confirmed parent/subcategories and deactivation-only on 2026-10-10.
  Category names are globally unique ignoring case and surrounding whitespace (max 100 characters).
  Position is nonnegative, with lower positions first among siblings and name/pk tie breaks.
  Parents may be inactive; the public list hides inactive categories and all their descendants.
  Reactivating a parent restores descendants whose own active flag is still true.
- Model validation rejects self-parenting and descendant cycles. PostgreSQL transaction advisory
  lock 734003004 serializes supported model/admin saves through cycle validation and persistence.
  Bulk/raw updates bypass model validation and are not supported hierarchy write paths.
- Application model/queryset deletion and admin deletion are disabled for every category,
  including unused categories. Existing rows and future product references remain intact.
  Parent FK uses PROTECT. Products do not exist yet; MVP-005 must use a protected category FK
  and test actual product references rather than treating this ticket as product validation.
- `/categories/` is a minimal escaped, server-rendered list of visible category paths with an
  empty state. It does not implement the later storefront design or product browsing ticket.
- Removing MVP-002 removes its two-instance local demonstration scope. It does not introduce
  shared-database tenancy or remove eventual independent deployment requirements.
